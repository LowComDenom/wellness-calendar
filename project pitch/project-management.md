# Project Management System

I will use a GitHub Projects board to track work across the backend and web repositories. The board will have Backlog, Ready, In Progress, Review, and Done columns. Each issue will describe one outcome, include acceptance criteria, identify whether it is frontend, backend, or integration work, and be assigned to one directly responsible person. Issues that span both repositories will link to each other and share the same acceptance criteria.

I will organize work around the course milestones: pitch approval, MVP and code review, deployment, defense, and presentation. At each stand-up, I will share completed work, current work, and blockers. Code changes will go through pull requests so they can be reviewed before merging. If I work solo, I will assign issues to myself and review changes against their acceptance criteria; if I work with a team, each issue will have one owner and another teammate will review the pull request.

## High-Level Tickets

1. Finalize the MVP data model and API contract.
2. Create the database schema and local mock data.
3. Implement account registration, login, and user-scoped access.
4. Implement API routes for creating, viewing, editing, and deleting notes.
5. Build the calendar view and daily note forms.
6. Connect the web UI to the API, including loading and error states.
7. Deploy the frontend and backend, then document how to use the deployed app.
